The problem, in one line

All three pages are built on .legal-hero and .legal-page, the components behind /privacy-policy. A press index and a founders story are wearing a legal document's layout, which is why they read as a different site from the homepage. After this patch, .legal-hero should appear only on /privacy-policy and /terms-and-conditions.

How it fits the codebase

Nothing in the existing stylesheet is edited or removed. redesign.css reuses the tokens already declared in :root and extends the existing .blog-*, .fd-* and .btn components in place.

Motion runs on the [data-reveal], [data-reveal-scale] and [data-hero-line] attributes already driving the homepage, so the same script picks these pages up with no changes. Buttons keep radius 0 and accents stay on thin brass rules, per the v3 component sheet. Slugs are unchanged, so no redirects.

What changes

/blogsRebuilt

Cinematic .page-hero in place of the navy band. A new sticky topic filter, typographic rather than pill-shaped, whose active state is a brass rule that slides in 280ms on --ease-out and snaps under prefers-reduced-motion. Card rhythm fixed so every Read More in a row sits on one line, structurally rather than by tuning copy.

/mediaRebuilt

Press coverage currently renders through blog cards with unrelated project renders as thumbnails, and the intro is copied word for word from Blogs. Replaced with an outlet strip, one lead story, two image-led stories and a typographic index. The Telugu lead gets lang="te", a Telugu face and an English gloss. A media enquiries block gives journalists a contact route.

/foundersExtended

.fd-hero-media ships with no <img> inside it, which is the entire reason that hero reads as a flat navy band. Adding the image plus a fact strip fixes it. Copy is cut to roughly half with every fact kept, and round chips become rules per the radius-0 guideline.

Before you ship

  • Add a Telugu face. Media needs one for the lead headline. Load Noto Serif Telugu at weights 400 and 500 on that route only. The CSS falls back to var(--serif) without it, so this is a refinement, not a blocker.
  • Move one image off the old domain. The Healthcare post still pulls its thumbnail from amaya-senior-living.vercel.app, the old mockup host.
  • Decide how Load More behaves. On Media it should append into .press-index. If Blogs moves to server-side pagination, render each topic as a link to /blogs?topic=<slug> and delete the filtering block in topics-filter.js; the sliding rule works either way.
  • Detail templates are untouched. .blog-article-* already looks well built, so this patch deliberately leaves it alone.
